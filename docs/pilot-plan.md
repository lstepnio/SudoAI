# SudoAI pilot plan

The first release targets two jobs. During a meeting, the user starts capture and sees which sources are active. After the meeting, the user can find a decision, action or slide and open the evidence behind it. The stock Omi pendant supplies an optional audio track. The Mac app lives in the system menu bar. The Pixel app keeps the normal Teams client and phone dialer.

## Research and design choices

| Project or platform | What applies to this pilot |
| --- | --- |
| Omi | The stock wearable publishes audio and its codec over Bluetooth LE. Read the codec before decoding. The DevKit and CV1 Opus modes use different frame durations, which affect timestamps and gap detection. Each native client claims one pendant and releases it for handoff. [Omi device protocol](https://github.com/BasedHardware/omi/blob/main/sdks/device/PROTOCOL.md) |
| Screenpipe | Screenpipe associates visible content with timestamps and extracts searchable text, including OCR when accessibility text is unavailable. SudoAI applies that idea to a window or display chosen for one session. It compares small frames locally and stores a changed image plus OCR. This keeps the screen timeline usable alongside speech and limits image volume. [Screenpipe capture design](https://github.com/screenpipe/screenpipe#how-it-works) |
| Anarlog, originally Hyprnote | Its local-first design demonstrates that note-taking can keep working while optional hosted services are unavailable. SudoAI journals native captures first, uses durable acknowledgments for upload, and shows original evidence next to generated meeting notes. [Anarlog](https://github.com/fastrepl/anarlog) |
| whisper.cpp | The project supports Android and macOS, including Apple Silicon acceleration. It provides a credible future offline speech engine. The pilot uses one hosted speech provider to avoid shipping and tuning models on both devices. Revisit local inference with the same recordings if measured cost, connectivity or data-handling requirements justify it. [whisper.cpp](https://github.com/ggml-org/whisper.cpp) |
| Apple capture APIs | A Core Audio process tap can select the output of specific processes. SudoAI uses that for the native Teams client and keeps the selected microphone on its own track. ScreenCaptureKit provides the system picker for screen moments. Test helper-process churn, headset changes and permission revocation on the actual Mac. [Apple Core Audio taps](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps) · [Apple sharing picker](https://developer.apple.com/documentation/screencapturekit/sccontentsharingpicker) |
| Android and Teams | Android playback capture depends on the source app's policy and audio usage. Ordinary apps cannot depend on capturing call downlink, and concurrent microphone use may produce silence. The app offers eligible playback, file import and an Omi speakerphone recording. Teams organizers or otherwise authorized users can obtain a VTT from Recap when tenant policy permits. A headset keeps remote speech out of the pendant's room recording. [Android playback capture](https://developer.android.com/media/platform/av-capture) · [Android audio-input sharing](https://developer.android.com/media/platform/sharing-audio-input) · [Android screen projection](https://developer.android.com/media/grow/media-projection) · [Teams transcripts](https://support.microsoft.com/en-gb/teams/meetings/start-stop-and-download-live-transcripts-in-microsoft-teams-meetings) |

## Parallel implementation and qualification

Freeze the capture and sign-in contract before splitting ownership. Each lane can use synthetic media, an isolated library or injected capture inputs while the others build. The integration lead owns shared contract changes and the combined release. Five lanes are useful even when the runtime schedules some in successive waves. [Capture contract](capture-contract.md)

| Lane | Ownership and dependencies | Deliverable and acceptance |
| --- | --- | --- |
| 1. Mac capture | SwiftUI menu extra, AVAudioEngine, Teams process tap, ScreenCaptureKit, Vision, CoreBluetooth and local journal. Consumes the capture contract. | Capture inputs have independent status. Pause, resume, BLE loss, an interrupted write and a network failure preserve accurate timings. A real Teams call with headphones must produce two intelligible tracks. [Mac implementation and test matrix](../macos/README.md) |
| 2. Android capture | Kotlin foreground service, MediaProjection, AudioRecord, BLE, Android Keystore, offline upload and the share sheet. Consumes the same contract. | A Pixel user can stop from the notification, revoke sharing, resume uploads after an offline period and import a Teams transcript once. Separately test speakerphone, headset and protected playback. [Android implementation and test matrix](../android/QA.md) |
| 3. Private library | FastAPI authentication, object ownership, SQLite/FTS, idempotent upload, retry, retention, export and deletion. Owns data model and API changes. | A repeated upload creates one object, a second account cannot access it, and an acknowledgment survives restart. Bookmarked material survives expiry and a clean restore. [Server and operator commands](../README.md) |
| 4. Meeting intelligence | Speech, VTT import, timeline, local OCR ingestion, summaries, actions, and questions with timestamped references. Depends on evidence IDs and job schema. | Score the same invented speech and screen facts across search, Q&A and reference verification. Unsupported questions must produce an abstention. Keep test accuracy, provider latency and real-meeting performance distinct. [Qualification fixture and results](../qa/README.md) |
| 5. Integration and release | Production Authentik group, one application container, Caddy, DNS, signing, installer delivery and device qualification. Depends on immutable server image and signed client artifacts. | A member signs in, anonymous access to the library API and installer returns 401, the downloaded APK matches its signed digest, and both public and LAN HTTPS reach the intended host. Verify backups and rollback scope. [Host runbook](self-hosting.md) |

## Release sequence

1. Run the server and native tests and replay the same audio, screen, gap and import contract. Exercise duplicate requests, sign-out while offline, interrupted uploads and local cleanup after acknowledgment.
2. Install on one operator's Mac and Pixel. Qualify sign-in, the private library and a short scripted meeting before adding users. Make the first call with people who know it is a recording test. Use known lines spoken by both ends and a known phrase visible only on a slide. Verify all three at the right points in the timeline.
3. During a 60-minute Teams session, change the headset, pause and resume, disconnect the network and reconnect the pendant. Check that missing sources produce explicit gaps and that playback continues normally. Record CPU, memory, battery, raw bytes per minute, upload backlog, time from stop to searchable text and provider usage. Use measurements from this hardware to set pilot limits.
4. Repeat on the physical Pixel with Teams and a regular call. Validate acoustic speakerphone capture separately from an authorized VTT import. Test screen lock, foreground-service notification, screen-picker dismissal and loss of Bluetooth. Check that an unavailable remote call track is visible to the user.
5. Admit additional group members after validating those results and identifying the Mac signing/distribution path. Test a second account in both directions, removal from the pilot and revocation of its active device tokens. Use the same scripted meeting for future regressions.
